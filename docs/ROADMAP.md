# Feature proposals after 3.7.0

This is the project's current proposal list. These features are **not implemented or promised for a particular release**. The baseline already includes after-exit updates, one-version program rollback, pause reminders, API quota handling, bandwidth windows, DMG selection and ASAR-safe installation.

| Priority | Proposal                             | User benefit                                                                              | Acceptance criteria                                                                                                                        |
| -------- | ------------------------------------ | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| P1       | Update policy per repository         | Automatically update low-risk tools while keeping critical tools manual.                  | Source override inherits the global policy by default and is included in import/export and bulk-edit previews.                             |
| P1       | Release channels and version pinning | Choose stable or prerelease builds and keep a known version until explicitly released.    | A pinned source never silently advances; channel changes have a visible preview and preserve installation rollback.                        |
| P1       | Package selection preview            | Explain why a particular asset will be downloaded and installed.                          | Show OS, architecture, format, signature requirements and exclusion reasons before changing files.                                         |
| P1       | Installation health report           | Distinguish download, verification, extraction, running-process and replacement failures. | One per-source diagnostic view shows the failing stage and a reversible retry action with redacted export.                                 |
| P2       | Scheduled recovery drills            | Prove that backups can be restored before a real failure.                                 | Restore selected backups into an isolated temporary location, verify content, record results and remove only owned test data.              |
| P2       | Historical backup generations        | Recover a repository from an earlier successful run.                                      | Explicit retention count/age/size limits, storage estimates and previewed cleanup; encrypted generations remain independently recoverable. |
| P2       | Adopt an existing installation       | Bring a manually installed tool under management without losing the original.             | Match the program and source explicitly, create a verified fallback copy and refuse ambiguous or foreign targets.                          |
| P2       | Optional post-install health checks  | Detect a broken update before relying on it.                                              | Only explicitly configured checks run, with timeouts and an optional rollback; no automatic interaction with connected hardware.           |
| P2       | Source-group maintenance windows     | Update a group only at appropriate times.                                                 | Separate backup and installation windows, timezone-aware previews and visible deferred work.                                               |
| P3       | Backup inventory comparison          | Compare two drives and locate missing or stale copies.                                    | Read-only comparison of managed identities, refs and manifests, with no automatic deletion.                                                |

Recommended next work: **per-source update policies**, followed by **release pinning** and **package-selection previews**. These extend the existing installer without first introducing historical backup storage.

Publisher certificates, notarization, automatic self-replacement of Git Cloner and submissions to public package stores are separate decisions; generated catalog templates do not constitute acceptance into a store.
